Module 8: Exploratory Data Analysis

Introduction

Before running a statistical model, calculating an index, or interpreting ecological patterns, we should first understand our data.

This process is called Exploratory Data Analysis, or EDA.

EDA helps us answer questions such as:

  • How much data do we have?
  • What does one row represent?
  • Which variables are available?
  • Are there missing or unusual values?
  • Which species were recorded?
  • How are records distributed among camera stations?
  • How are records distributed through time?
  • Are there patterns that deserve further investigation?

EDA is about understanding the dataset well enough to decide what questions we can reasonably ask next.

Importante

Exploration comes before interpretation.

Finding a pattern in a graph does not necessarily mean that we have found an ecological mechanism.

Step 3: Look for missing information

Real ecological datasets almost always contain missing values.

Missing information is not necessarily a problem.

But we need to know where it occurs.

For example:

recordTable |>
  summarise(
    missing_sex = sum(is.na(Sex)),
    missing_age = sum(is.na(Age)),
    missing_identifier = sum(is.na(Identifier))
  )
# A tibble: 1 × 3
  missing_sex missing_age missing_identifier
        <int>       <int>              <int>
1         100          87               3692

Remember:

is.na()

returns TRUE when a value is missing.

Because R treats TRUE as 1 and FALSE as 0 in this context:

sum(is.na(Age))

counts the number of missing values.

Missing values are not the whole story

Sometimes missing or uncertain information is represented using a category instead of NA.

For example:

recordTable |>
  count(
    Age,
    sort = TRUE
  )
# A tibble: 4 × 2
  Age          n
  <chr>    <int>
1 Adult     2563
2 Unknown   1177
3 <NA>        87
4 Juvenile    71

and:

recordTable |>
  count(
    Sex,
    sort = TRUE
  )
# A tibble: 4 × 2
  Sex         n
  <chr>   <int>
1 Unknown  2727
2 Famale    547
3 Male      524
4 <NA>      100

A value such as:

Unknown

is not technically missing to R.

It is a character value.

But biologically, it may still represent information that we do not know.

Importante

R only knows what is written in the dataset.

It does not know that:

Unknown

may represent missing biological information.

Understanding what values mean requires knowledge of how the data were collected.

  ggplot( aes(  x = reorder(Species, n),  y = n  )) +

    y = "Number of records",
    title = "Camera-trap records by species"  ) +

Notice that we are combining:

data manipulation
        ↓
visualization

inside the same pipeline.

Be careful with record counts

A species with more records is not necessarily more abundant.

For example:

more records

could result from:

  • more activity,
  • longer visits in front of the camera,
  • differences in detection probability,
  • differences in camera effort,
  • or actual differences in abundance.
Records are not the same as abundance

Throughout this exploratory analysis, we are describing the records contained in the dataset.

We should not automatically interpret:

more records = more animals

Camera-trap detections are influenced by both ecological and observation processes.

Some stations may have many more records than others.

Why?

Possible explanations include:

animal activity
habitat
camera placement
camera operation time
technical failures
sampling duration

The graph alone cannot tell us which explanation is correct.

Records are not sampling effort

This distinction is especially important for camera-trap data.

Suppose:

Camera A = 500 records

Camera B = 50 records

That does not tell us how long each camera was operating.

Camera A may have operated for 100 days and Camera B for only 10 days.

Our recordTable contains detection records.

It does not by itself describe the complete sampling effort of cameras with no detections or periods when cameras were inactive.

Importante

Do not use the number of records at a station as a measure of camera effort.

To calculate effort, we need information about when each camera was operating.

We will return to this idea when we begin working with camera-trap-specific tools.

Notice the wording:

observed species richness

We are describing the number of species recorded in our dataset.

We are not claiming that this is the true number of species using each site.

Records and observed richness

We can also explore whether stations with more records tend to contain more observed species.

ggplot(
  station_summary,
  aes(
    x = records,
    y = species_richness
  )
) +
  geom_point(
    size = 3
  ) +
  labs(
    x = "Number of records",
    y = "Observed species richness"
  ) +
  theme_bw()

You may notice that stations with more records often also contain more species.

Does that mean that those stations have better habitat?

Not necessarily.

Nota

Stations with more sampling effort or more detections have more opportunities to record additional species.

This is why exploratory relationships should not automatically be interpreted as ecological effects.

EDA is an iterative process

Exploration rarely follows a perfectly linear sequence.

You may begin with:

How many species do I have?

Then notice:

One station has very few records.

That may lead you to ask:

Was that camera operating throughout the study?

Then:

Do all species show the same pattern?

Then:

Does the pattern change through time?

EDA often looks like:

question
   ↓
summary
   ↓
visualization
   ↓
something interesting or strange
   ↓
new question
   ↓
check the data
   ↓
repeat

What EDA cannot tell us

Exploratory analysis is extremely useful.

But it has limits.

From these graphs alone, we cannot conclude that:

a habitat causes more detections

one station has greater abundance

one species prefers a treatment

a temporal change reflects population change

Those conclusions require appropriate study design, effort information, and statistical analyses.

Importante

EDA helps us describe patterns and generate hypotheses.

It does not automatically establish causation or account for detectability.

There is no single correct solution because exploratory analysis depends on the questions you ask.

One possible workflow could be:

library(tidyverse)

recordTable <- read_csv(
  "data/recordTable.csv"
)


# ---------------------------
# Dataset overview
# ---------------------------

recordTable |>
  summarise(
    records = n(),
    stations = n_distinct(Station),
    species = n_distinct(Species),
    first_record = min(Date),
    last_record = max(Date)
  )


# ---------------------------
# Inspect data quality
# ---------------------------

recordTable |>
  count(
    Sex,
    sort = TRUE
  )

recordTable |>
  count(
    Age,
    sort = TRUE
  )

summary(
  recordTable$N_individuals
)


# ---------------------------
# Explore one species
# ---------------------------

deer_records <- recordTable |>
  filter(
    Species == "White-tailed deer"
  )

deer_records |>
  summarise(
    records = n(),
    stations = n_distinct(Station)
  )


# Records by station

deer_station <- deer_records |>
  count(
    Station,
    sort = TRUE
  )

ggplot(
  deer_station,
  aes(
    x = reorder(Station, n),
    y = n
  )
) +
  geom_col(
    fill = "steelblue"
  ) +
  coord_flip() +
  labs(
    x = "Camera station",
    y = "Number of records"
  ) +
  theme_bw()


# Records through time

deer_daily <- deer_records |>
  count(Date)

ggplot(
  deer_daily,
  aes(
    x = Date,
    y = n
  )
) +
  geom_line() +
  labs(
    x = "Date",
    y = "Number of records"
  ) +
  theme_bw()
